# Настройка безопасности Messenger

Перед следующим деплоем добавь в Render → Service → Environment:

- `SUPABASE_URL` — URL проекта Supabase.
- `SUPABASE_SERVICE_ROLE_KEY` — новый service-role ключ Supabase.
- `SESSION_SECRET` — случайная строка не короче 32 символов.
- `TURN_USERNAME` и `TURN_CREDENTIAL` — новые TURN-реквизиты для звонков.
- `NODE_ENV=production`.

Не помещай секреты в Git, HTML или Android-проект. Старые Supabase/TURN-значения, ранее опубликованные в репозитории, необходимо отозвать и заменить.

## Изменения

- Вход только с паролем; вход по одному логину отключён.
- Старые пароли переводятся на scrypt-хеш при первом успешном входе; новые пароли хранятся в виде хеша.
- Журнал больше не содержит старые и новые пароли.
- Ограничены попытки входа, усилены cookie сессии, сессия обновляется после входа.
- Добавлены лимиты размера и типа загружаемых файлов; загрузка требует авторизации.
- Страницы отдаются через маршруты приложения, а не через открытую раздачу корня проекта.
- Android signing credentials читаются из переменных окружения.

Опубликованный Android keystore следует считать скомпрометированным. Не заменяй ключ подписи уже выпущенного приложения без плана обновления: это может помешать установке обновлений поверх старой версии.

Существующие пароли в Supabase не меняются массово: они преобразуются в scrypt-хеши по мере успешного входа пользователей. Публичные копии файлов и Git-история требуют отдельной проверки; удаление файла из новой версии не стирает старые коммиты.
